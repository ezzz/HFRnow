# Cycle de revue de la PR $ARGUMENTS

Suivre `.harness/docs/REVIEW-ROUNDS.md` (sinon `${CLAUDE_PLUGIN_ROOT}/docs/REVIEW-ROUNDS.md`) :

1. **Tout lire** : commentaires en ligne, « Outside diff range », détails, « Prompt for AI agents », **chaque** fil ouvert,
   l'état des contrôles. Relire la tête de branche (SHA) : un constat sur une ancienne tête est peut-être déjà réglé.
2. Pour chaque constat, **tracer un vrai chemin** (entrée → défaillance). Le classer : réel → corriger ; infondé ou
   disproportionné → réponse argumentée ; **sécurité → reste ouvert jusqu'à la décision du mainteneur**.
3. **Corriger la classe** : autres points d'entrée, motif identique ailleurs, ordre inverse, autres limites. Un test par
   cas, vu en échec sans le correctif.
4. **Contre-vérification** : un sous-agent séparé reçoit les constats, le diff et `LESSONS.md` (pas tes conclusions) et
   cherche ce que le correctif rate ou casse. Intégrer.
5. **Un commit, un push** pour tout le cycle. Les détails facultatifs ne déclenchent pas de push à eux seuls.
6. **Une réponse par fil** (commit correctif ou raison), puis résoudre le fil ; constats hors diff : un commentaire de PR.
   Chaque réponse finit par le pied `---` / `_Generated by [Claude Code](https://claude.ai/code)_`.
7. Vérifier que le bot a relu **la nouvelle tête** ; sinon demander à l'opérateur de poster `@coderabbitai review`
   (les mentions postées depuis le cloud sont altérées).
8. Contrôle en échec en quelques secondes sans journal = infrastructure, pas « CI rouge » ; une relance au plus.
9. **Leçons** : chaque constat déjà couvert par `LESSONS.md` = étape d'auto-relecture à resserrer ; genre nouveau =
   proposer une ligne (au projet, ou au cadre par PR si elle vaut ailleurs).
